# 💊 ผู้ช่วยยาสามัญประจำบ้าน (Household Medicine RAG Chatbot)

แชตบอตตอบคำถามเรื่อง **ยาสามัญประจำบ้านของไทย** ด้วยเทคนิค RAG (Retrieval-Augmented Generation)
ระบบค้นหาข้อมูลจากคลังเอกสารก่อน แล้วให้ LLM ตอบจากเอกสารที่ค้นได้เท่านั้น พร้อมแสดงแหล่งอ้างอิงทุกครั้ง

- **Web App:** https://labfinalnlp-czysquxhqbgcpbsgvfewbr.streamlit.app/
- **Source Code:** https://github.com/Alif024/LabFinal_NLP
- **ข้อจำกัด:** ใช้เพื่อการศึกษา ไม่ใช่คำแนะนำทางการแพทย์

## แนวคิดของ Domain

ยาสามัญประจำบ้านเป็นยาที่คนทั่วไปซื้อใช้เองได้โดยไม่ต้องมีใบสั่งแพทย์ แต่คนส่วนใหญ่ไม่รู้ว่ายาตัวไหนอยู่ในกลุ่มนี้
ใช้รักษาอาการอะไร หรือมีข้อควรระวังอะไร คำถามแบบนี้ต้องการคำตอบที่ **ถูกต้องและตรวจสอบที่มาได้**
ซึ่ง RAG เหมาะกว่าการให้ LLM ตอบจากความจำ เพราะ:

1. รายการยาอ้างอิง **ประกาศกระทรวงสาธารณสุข พ.ศ. 2568** ซึ่งใหม่กว่าข้อมูลที่ LLM ส่วนใหญ่เคยเรียนรู้
2. ทุกคำตอบอ้างอิงเอกสารต้นทาง ผู้ใช้กดลิงก์ไปตรวจสอบได้
3. ถ้าเอกสารไม่มีข้อมูล ระบบตอบว่า "ไม่พบข้อมูลในเอกสาร" แทนการเดา (สำคัญมากสำหรับเรื่องยา)

## แหล่งที่มาของเอกสาร

เอกสารทั้งหมดใน `data/` ดึงจาก **Wikipedia ภาษาไทย** (สัญญาอนุญาต [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/))
ผ่าน MediaWiki API เป็นข้อความล้วน ไม่ต้องทำ OCR จาก PDF ทุกไฟล์มีบรรทัด `แหล่งที่มา:` เก็บ URL พร้อม revision id ไว้
จึงเปิดดูต้นฉบับฉบับที่ใช้จริงได้เสมอ

| ไฟล์ | เนื้อหา | แหล่งที่มา |
|---|---|---|
| `00_ภาพรวม...` | นิยามและรายชื่อ 16 กลุ่มยา | [ยาสามัญประจำบ้าน](https://th.wikipedia.org/wiki/ยาสามัญประจำบ้าน) |
| `01`–`16` | รายการยาแต่ละกลุ่ม: ชื่อตำรับ ตัวยาสำคัญ สรรพคุณ ขนาดบรรจุ | [ยาสามัญประจำบ้าน](https://th.wikipedia.org/wiki/ยาสามัญประจำบ้าน) (อิง[ประกาศกระทรวงสาธารณสุข พ.ศ. 2568](https://ratchakitcha.soc.go.th/documents/81120.pdf)) |
| `20_พาราเซตามอล` | ขนาดยา ความเป็นพิษต่อตับ | [พาราเซตามอล](https://th.wikipedia.org/wiki/พาราเซตามอล) |
| `21_แอสไพริน` | ฤทธิ์ข้างเคียง กลุ่มอาการไรย์ | [แอสไพริน](https://th.wikipedia.org/wiki/แอสไพริน) |
| `22_คลอเฟนะมีน` | ยาแก้แพ้ อาการข้างเคียง | [คลอเฟนะมีน](https://th.wikipedia.org/wiki/คลอเฟนะมีน) |
| `23_มะขามแขก` | สมุนไพรยาระบาย | [มะขามแขก](https://th.wikipedia.org/wiki/มะขามแขก) |
| `24_ยาหม่อง` | ประวัติและสรรพคุณ | [ยาหม่อง](https://th.wikipedia.org/wiki/ยาหม่อง) |
| `25_ยาดม` | ยาดม | [ยาดม](https://th.wikipedia.org/wiki/ยาดม) |

รวม **23 ไฟล์ ประมาณ 55,000 ตัวอักษร** สร้างใหม่ได้ด้วยคำสั่ง `python scripts/build_data.py`
สคริปต์แปลงตาราง wikitext ให้ยา 1 ตำรับเป็น 1 หัวข้อที่อ่านเข้าใจได้ในตัวเอง (ชื่อตำรับ, กลุ่มยาและเลขรายการตามประกาศฯ,
สรรพคุณ, ขนาดบรรจุ, ตัวยาสำคัญ) เพิ่มหัวข้อ "รายชื่อยาในกลุ่ม" ให้แต่ละกลุ่ม และแปลงหัวข้อของบทความ Wikipedia เป็นหัวข้อ `## `
(ตัดหัวข้อที่ไม่มีเนื้อหา เช่น "คลังภาพ") ตัวอย่างข้อมูล 1 ตำรับ:

```
## ยาเม็ดบำรุงโลหิต เฟอร์รัส ซัลเฟต
กลุ่มยา: กลุ่มที่ 16 ยาบำรุงร่างกาย (รายการที่ 3 ตามประกาศฯ)
สรรพคุณ: รักษาโลหิตจางเนื่องจากขาดธาตุเหล็กในผู้ใหญ่
ขนาดบรรจุ: ภาชนะบรรจุขนาดไม่เกิน 10 เม็ด
ตัวยาสำคัญและความแรง:
ตัวยาสำคัญในสูตรตำรับ 1 เม็ด
  - Ferrous Sulfate สมมูลกับ Iron 60 มิลลิกรัม
```

## สถาปัตยกรรมระบบ RAG

```
คำถาม ─► (1) Condense ─► (2) Hybrid search ─────────────► (3) Prompt + Context ─► Groq LLM ─► (4) จัดเลขอ้างอิง ─► คำตอบ + เอกสารอ้างอิง
          (เฉพาะคำถาม     e5 + FAISS  (ความหมาย)    RRF     ตอบจาก context เท่านั้น              เรียง [1],[2] ตามลำดับที่อ้าง
          ต่อเนื่อง)       BM25 คำ+พยางค์ (คำสำคัญ)  รวมอันดับ  อ้าง [n] / "ไม่พบข้อมูล"           แสดงเฉพาะเอกสารที่ถูกอ้างจริง
```

โค้ดแยกเป็น `rag.py` (pipeline ทั้งหมด) และ `app.py` (หน้าเว็บ Streamlit) เพื่อให้ `scripts/evaluate.py` ทดสอบด้วย pipeline เดียวกับหน้าเว็บ

| ขั้นตอน | รายละเอียด |
|---|---|
| **Document Loading & Cleaning** | อ่าน `data/*.txt` แยกส่วนหัว (ชื่อ/แหล่งที่มา) ออกจากเนื้อหา แล้วทำความสะอาดด้วย `pythainlp.util.normalize` (แก้สระ/วรรณยุกต์ซ้ำ) ลบ zero-width space และช่องว่างเกิน |
| **Chunking** | แบ่งตามหัวข้อก่อน: **ยา 1 ตำรับ = 1 chunk** และหัวข้อของบทความไม่ถูกรวมข้ามกัน ย่อหน้าในหัวข้อเดียวกันรวมได้ไม่เกิน 900 ตัวอักษร ย่อหน้าที่ยาวเกินถูกตัดซ้อนกัน 150 ตัวอักษรที่ขอบเขตคำ (บรรทัด → ช่องว่าง → ขอบเขตคำจาก pythainlp จึงไม่ตัดกลางคำไทย) ทุก chunk มี **ชื่อเอกสาร + หัวข้อ** กำกับ (contextual header) ได้ 113 chunks ยาวสุด 364 token (ไม่เกิน 512 ของโมเดล) |
| **Embedding** | [`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small) (118M พารามิเตอร์ รองรับภาษาไทย) ใส่ prefix `passage:` / `query:` ตามที่โมเดลกำหนด และ normalize เวกเตอร์ |
| **Vector Search** | FAISS `IndexFlatIP` (inner product ของเวกเตอร์ normalize = cosine similarity) |
| **Keyword Search** | BM25 (`rank-bm25`) บนคำและพยางค์จาก pythainlp (`newmm` + `syllable_tokenize`) ตัด stopword ภาษาไทย พยางค์ช่วยให้คำประสมที่ตัดคำต่างกันยังจับคู่กันได้ เช่น "ยาบำรุง\|เลือดจาง" กับ "ยาเม็ด\|บำรุง\|โลหิต\|จาง" |
| **Hybrid + RRF** | รวมอันดับของทั้งสองวิธีด้วย Reciprocal Rank Fusion (k = 60) แล้วเลือก top-k (ค่าเริ่มต้น 5) โมเดลและ index โหลดครั้งเดียวด้วย `@st.cache_resource` |
| **Condense Question** | เฉพาะคำถามต่อเนื่อง LLM เขียนคำถามใหม่ให้สมบูรณ์ในตัวก่อนค้นหา (เช่น "ถ้าดื่มเหล้าล่ะ" → "ถ้าดื่มเหล้าเป็นประจำ กินพาราเซตามอลได้วันละไม่เกินเท่าไร") โดย prompt ห้ามใส่คำตอบลงในคำถาม คำถามแรกใช้ตามที่ผู้ใช้พิมพ์ |
| **Prompt Engineering** | System prompt (`SYSTEM_PROMPT` ใน `rag.py`) บังคับให้ตอบจาก `<context>` เท่านั้น อ้างอิง `[n]` เฉพาะเอกสารที่มีข้อมูลนั้นจริง ตอบ "ไม่พบข้อมูลในเอกสาร" เมื่อไม่มีคำตอบ (ยกเว้นเอกสารระบุชัดว่า "ไม่มี") ระบุทุกรายการเมื่อถามว่า "มีอะไรบ้าง" และเตือนให้ปรึกษาเภสัชกรเฉพาะคำถามเรื่องขนาดยา/ความปลอดภัย ใช้ temperature 0.1 |
| **LLM** | Groq API (`openai/gpt-oss-120b` ค่าเริ่มต้น เปลี่ยนได้ผ่าน secret `GROQ_MODEL`) แสดงคำตอบแบบ streaming ถ้าโควตารายวันของโมเดลหลักเต็ม (HTTP 429) จะสลับไปใช้ `openai/gpt-oss-20b` ซึ่งมีโควตาแยกโดยอัตโนมัติ |
| **การอ้างอิง** | หลังได้คำตอบ ระบบจัดเลขอ้างอิงใหม่ตามลำดับที่ปรากฏในคำตอบ (เอกสารที่ถูกอ้างถึงก่อนเป็น [1]) ตัดเลขที่ไม่มีเอกสารจริง แปลง `【1】` เป็น `[1]` และแสดงเฉพาะเอกสารที่คำตอบอ้างถึง ส่วนผลค้นหาที่ไม่ได้ใช้แสดงเป็นรายชื่อด้านล่าง |
| **Conversation** | เก็บประวัติแชตใน `st.session_state` ส่งประวัติล่าสุดให้ LLM (ลบเลขอ้างอิงของคำตอบเก่าออก เพราะเลขผูกกับเอกสารของคำถามนั้น ๆ) |
| **Interface** | หน้าแชต (`st.chat_message`) แสดงเอกสารอ้างอิงที่ใช้ตอบใต้ทุกคำตอบ (ชื่อ ลิงก์ ไฟล์ อันดับผลค้นหา ความใกล้เคียง ข้อความต้นทาง) ไม่แสดงเมื่อตอบว่า "ไม่พบข้อมูลในเอกสาร" มีปุ่มคำถามตัวอย่าง ปรับ top-k ได้ ปุ่มล้างแชต และรายชื่อเอกสารทั้งหมด |

## การประเมินผล

รัน `python scripts/evaluate.py` (ใช้ pipeline เดียวกับหน้าเว็บ ต้องมี `GROQ_API_KEY`) หรือ `--retrieval-only` เพื่อทดสอบเฉพาะการค้นหา

### 1. การค้นหา (Retrieval)

ชุดทดสอบ: `test_questions.csv` 17 ข้อที่มีคำตอบ (ตรวจระดับไฟล์) และ `scripts/retrieval_dev.csv` คำถามภาษาพูด 30 ข้อ
ที่ใช้คำไม่ตรงกับเอกสาร เช่น "ถ่ายไม่ออก" หรือ "เท้าเปื่อย" (ตรวจระดับรายการยา) hit@k คือสัดส่วนคำถามที่เจอเอกสารที่ถูกใน k อันดับแรก

| วิธีค้นหา | test hit@1 | test hit@5 | dev hit@1 | dev hit@3 | dev hit@5 | dev MRR |
|---|---|---|---|---|---|---|
| vector (e5 + FAISS) | 0.94 | 1.00 | 0.57 | 0.67 | 0.83 | 0.65 |
| BM25 (คำ + พยางค์) | 0.94 | 0.94 | 0.73 | 0.90 | 1.00 | 0.84 |
| **hybrid (RRF) ที่ใช้จริง** | **1.00** | **1.00** | **0.67** | **1.00** | **1.00** | **0.82** |

การทดลองที่ใช้เลือกการตั้งค่า (dev 30 ข้อ):
- **chunk ละ 1 ตำรับยา** แทน chunk ที่รวมหลายตำรับ: ทำให้เอกสารอ้างอิงตรงกับยาที่ตอบ (เดิม 16 จาก 42 chunk มีหลายตำรับปนกัน)
- **BM25 ระดับพยางค์** ช่วยคำประสม: BM25 ระดับคำอย่างเดียว dev hit@5 = 0.87 เพิ่มพยางค์แล้วได้ 1.00
- **multilingual-e5-base** (ใหญ่กว่า) ได้ hit@1 ดีขึ้น (0.80) แต่ hit@5 ลดลง (0.93) และใช้หน่วยความจำ ~2.0 GB เทียบกับ ~1.4 GB จึงเลือก e5-small ซึ่งเหมาะกับ Streamlit Cloud
- **ให้ LLM สร้างคำค้นเพิ่มเติม** (query expansion) ทำให้แย่ลง (dev hit@5 1.00 → 0.83) เพราะได้คำค้นยาวและไม่ตรงประเด็น จึงไม่ใช้
  แต่ใช้ **พจนานุกรมคำพ้องขนาดเล็ก** (`SYNONYMS` ใน `rag.py` เช่น เลือด → โลหิต, ปวดหัว → ปวดศีรษะ) แทน
  ซึ่งทำให้คำถาม "ยาบำรุงเลือดจาง..." เจอยาเม็ดบำรุงโลหิต เฟอร์รัส ซัลเฟตเป็นอันดับ 1 (เดิมอันดับ 4)

### 2. การตอบคำถามและการอ้างอิง (LLM จริง)

แต่ละข้อต้องผ่านครบ: ตอบได้ (ไม่ปฏิเสธ), อ้างอิงไฟล์ที่ถูก และมีข้อเท็จจริงสำคัญ (`key_facts`) ส่วนคำถามที่ไม่มีในเอกสารต้องตอบ "ไม่พบข้อมูลในเอกสาร"

| รอบทดสอบ | ผลลัพธ์ |
|---|---|
| ชุดเต็ม 19 ข้อ + บทสนทนาต่อเนื่อง 2 ชุด (`openai/gpt-oss-20b`) | **ผ่าน 19/19 ข้อ และ 2/2 บทสนทนา** |
| ตรวจซ้ำหลังปรับครั้งสุดท้าย (พจนานุกรมคำพ้อง, กฎเรื่องสรรพคุณ, ย้ำการอ้างอิง) ข้อ 3, 6, 10, 11, 13, 16, 19, 20 | ผ่านทั้ง 8 ข้อ (ข้อ 10 ผ่านหลังเพิ่มข้อความย้ำการอ้างอิง) |

หมายเหตุ: รอบหลังใช้ `gpt-oss-20b` เพราะโควตารายวันของ `gpt-oss-120b` (200,000 token/วัน บน Groq free tier) หมดระหว่างพัฒนา
รอบก่อนหน้าด้วย `gpt-oss-120b` (ก่อนปรับ prompt ครั้งสุดท้าย) ผ่าน 18/19 ข้อ

### 3. ปัญหาที่พบระหว่างทดสอบและการแก้ไข

| ปัญหา | การแก้ไข |
|---|---|
| คำตอบอ้างอิงเอกสาร [2] แต่ [1] เป็นเอกสารที่ไม่เกี่ยวข้อง และตำรับยาที่ใช้ตอบอยู่ลำดับที่ 3 ใน chunk | chunk ละ 1 ตำรับ, จัดเลขอ้างอิงตามลำดับในคำตอบ และแสดงเฉพาะเอกสารที่ถูกอ้างอิง |
| "ยาบำรุงเลือด" ค้นไม่เจอ "ยาบำรุงโลหิต" แล้ว LLM แนะนำวิตามินพร้อมอ้างสรรพคุณที่เอกสารไม่ได้เขียน | BM25 ระดับพยางค์ + พจนานุกรมคำพ้อง + กฎ "แนะนำยาเฉพาะเมื่อสรรพคุณในเอกสารตรงกับอาการ" |
| ขั้นตอนเขียนคำถามต่อเนื่องใหม่ ตอบคำถามเองจนมีตัวเลขคำตอบปนในคำค้น | prompt ห้ามตอบ/ห้ามใส่ตัวเลข และใช้เฉพาะคำถามต่อเนื่อง |
| LLM อ้างอิงหลายรูปแบบ (`【1】`, `<doc id="1">`, "เอกสารที่ 1") ทำให้เลขไม่ตรงกับรายการอ้างอิง | `normalize_citations()` แปลงทุกรูปแบบเป็น `[n]` ก่อนจัดเลขใหม่ |
| เอกสารระบุว่ากลุ่มยา "ไม่มี" รายการ แต่ LLM ตอบว่าไม่พบข้อมูล | ข้อยกเว้นพร้อมตัวอย่างใน prompt |

## วิธีใช้งาน

### ใช้งานบนเว็บ
1. เปิด https://labfinalnlp-czysquxhqbgcpbsgvfewbr.streamlit.app/
2. พิมพ์คำถามในช่องแชต หรือกดคำถามตัวอย่างที่แถบด้านซ้าย
3. อ่านคำตอบ ตัวเลข `[n]` คือหมายเลขเอกสารอ้างอิง กด **📚 เอกสารอ้างอิงที่ใช้ตอบ** เพื่อดูข้อความต้นทางและลิงก์ (เลข [n] ในคำตอบตรงกับลำดับในรายการ)
4. ถามต่อเนื่องได้ เช่น "พาราเซตามอลกินได้วันละเท่าไร" แล้วตามด้วย "ถ้าดื่มเหล้าล่ะ"

### รันบนเครื่องตัวเอง
```bash
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # แล้วใส่ GROQ_API_KEY
streamlit run app.py
```

### Deploy บน Streamlit Community Cloud
1. Push repo ขึ้น GitHub (ตรวจว่า **ไม่มี** `.streamlit/secrets.toml` ใน repo)
2. ที่ [share.streamlit.io](https://share.streamlit.io) เลือก repo และไฟล์หลัก `app.py`
3. **Advanced settings** เลือก Python 3.12 และใส่ใน **Secrets**:
   ```toml
   GROQ_API_KEY = "gsk_..."
   GROQ_MODEL = "openai/gpt-oss-120b"
   ```
4. Deploy แล้วลองเปิดในโหมด Incognito

## ตัวอย่าง Prompt ที่ใช้สั่ง AI

โปรเจกต์นี้พัฒนาร่วมกับ AI ผู้ช่วยเขียนโปรแกรม (Claude Code) ตัวอย่าง prompt ที่ใช้:

1. `NLP-SubTest2.ipynb จากไฟล์นี้สรุปสิ่งที่ต้องทำ`
2. `แนะนำหัวข้อที่ไม่ได้อยู่ในตัวอย่างมาให้หน่อย`
3. `อยากได้พร้อมข้อมูลอ้างอิงด้วยว่าแหล่งข้อมูลมาจากไหน ขอหัวข้อที่มีแหล่งข้อมูลที่เป็นข้อความหากเป็นไปได้ ถ้าเป็นไฟล์ pdf จะมีความเสี่ยงด้าน ocr`
4. `อยากได้หัวข้อ ผู้ช่วยยาสามัญประจำบ้าน` (AI ช่วยเขียนสคริปต์ดึงข้อมูล, app.py, คำถามทดสอบ และทดสอบ retrieval)

5. `ทำไมเอกสารอ้างอิงที่เลือกมาต้องอยู่ลำดับที่ 3 ไม่ได้มาเป็นอันดับแรก อยากให้ตรวจสอบความสอดคล้องและถูกต้องของ webapp นี้อย่างละเอียด พร้อมแก้ไขให้ถูกต้องสมบูรณ์ด้วย`
   (AI ช่วยวิเคราะห์สาเหตุ ทดลองเทียบวิธีค้นหา และแก้ตามหัวข้อ "ปัญหาที่พบระหว่างทดสอบและการแก้ไข")

Prompt ที่ระบบใช้สั่ง LLM ขณะตอบคำถามอยู่ในตัวแปร `SYSTEM_PROMPT` และ `CONDENSE_PROMPT` ใน `rag.py`
